# Geeky Realtime design — 2026-10-28
User accepted the proposed text/optional voice agent, campus controls, gestures, and quote-driven changes, delegating additional useful functionality. User requested agent source versioned in GuateGeeks/geeky-agent. Cotizador baseline: 47bc9337a9633d2a536f965f7fd701ec5313b608.
## Experience
Spanish-first Geeky welcomes visitors with a local greeting. Connect on first text send or explicit voice activation. Text remains usable without microphone permission. Voice off stops microphone tracks and playback; preserve conversation. A persistent accessible companion panel lives outside #app and survives wizard redraws. Match existing plum/orange/cream design. Keep manual workflow and no-WebGL experience complete.
## Architecture
geeky-agent: dependency-free ESM Node 22 HTTP server, browser ESM Realtime WebRTC client and fixed tool definitions. Browser talks to configured backend /session; backend exchanges SDP with POST https://api.openai.com/v1/realtime/calls using server-only OPENAI_API_KEY and model gpt-realtime-2.1. Model configurable by environment. No API key in frontend, source or logs.
Cotizador: semantic adapter with validated atomic actions, authoritative motor snapshots, revision checking and bounded undo; scene facade with bounded controls and allowed Geeky cues; companion UI; vendored pinned browser module from agent repository with provenance and reproducible sync command. Keep agent implementation solely owned by geeky-agent.
## Shared contract
Agent module exports createRealtimeClient({endpoint, executeTool, onEvent}). Methods: connect({voice=false}={}), sendText(text), setVoice(enabled), disconnect(). async methods reject on failure. executeTool(name,args) returns JSON result. onEvent(event): {type:'status',status:'connecting'|'connected'|'disconnected'}; {type:'message',id,role:'user'|'assistant',text,final:boolean}; {type:'voice',enabled:boolean}; {type:'error',message}; {type:'action',name,result}. Client handles transcripts, tool deduplication, sequential execution, response serialization, cancellation, connection timeout and stale async completion on disconnect. No greeting API response required; local greeting in UI.
Fixed server function tools: get_cotizador_context({}), update_cotizador({action,args,expectedRevision}), control_campus({action,args}), undo_cotizador({expectedRevision}). Tools describe command format and request context before mutations. update actions: set_levels, set_students, add_section, remove_section, add_program, remove_program, set_program_groups, set_schedule, set_equipment, set_modality, set_tax, set_projection, navigate, calculate.
Adapter exposed as window.GGCotizadorAgent with getContext(), executeTool(name,args). Context includes revision, catalog, current selection, enrollment/groups with ids, validated permitted actions and exact argument shapes, authoritative totals/pending/warnings, scene capabilities. Mutations return {ok,revision,message,context}; failures {ok:false,error,...} and change nothing. Host integration may extend asesor.js with window.GGCotizadorHost encapsulating state and render/motor access.
Camera tool action enum: focus (args kind program|level|overview, id), view (name overview|front|patio|people|program), rotate (direction left|right), zoom (direction in|out), reset, pause (paused boolean), show (visible boolean), gesture (name greet|nod|point|celebrate). Strict local validation, scene absence returns actionable failure. Never invent prices or modify upstream Geeky geometry.
## Safety and lifecycle
Limit request bodies and incoming text, origin allowlist, rate limits, upstream timeout, secret-redacted errors and no transcript logs. Local development works with explicit localhost origins. Server not an authentication provider; document public endpoint exposure and production TLS/proxy/rate-limit setup. Missing backend preserves static greeting and manual quote flow with clear setup/unavailable error. Microphone denial returns text mode. Closing panel terminates connection and microphone.
No publishing to main for Cotizador; branch and PR. Empty agent repo can have initial documentation main commit to establish PR base, feature code via PR. No live deployment assumed.

SDK vs direct WebRTC: use direct documented WebRTC to preserve plain JS stack and exact no-mic text lifecycle. Separate hosted backend vs moving site: keep GitHub Pages and provide a small independently deployable backend. These are implementation decisions delegated by user.
